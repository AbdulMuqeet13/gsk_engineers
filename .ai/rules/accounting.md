# Accounting Rules

## Money Handling (CRITICAL)
- Store all monetary amounts as `decimal(18,2)` in the database
- Perform all arithmetic using `bcmath` functions: `bcadd()`, `bcsub()`, `bcmul()`, `bcdiv()` with scale 2
- **NEVER** use native PHP floats for money — float arithmetic produces rounding errors
- Compare money values with `bccomp($a, $b, 2)`, never `==` or `===`

## Double-Entry Invariant
- Every posted journal entry MUST have `sum(debit) == sum(credit)` — enforced in `JournalService::post()`
- Every journal entry MUST have at least two lines
- If the invariant fails, the transaction rolls back — no partial posting
- The trial balance must always balance (total debits == total credits across all accounts)

## Immutability
- **Posted entries are immutable** — never update or delete posted journal entries or their lines
- To correct a posted entry, create a **reversing entry** (a new journal entry that mirrors the original with swapped debits/credits)
- Draft entries are editable until posted
- Use soft deletes on master data (account heads, projects); use status-based immutability on financial records

## Project Dimension
- Every journal line can carry an optional `project_id`
- Project-wise reports are generated by filtering journal lines on `project_id`, not by copying data
- Inter-project transfers create entries with lines tagged to both source and target projects

## Account Heads
- `normal_balance` is `debit` for Asset and Expense accounts, `credit` for Liability, Equity, and Income accounts
- Running balance is calculated as: for debit-normal accounts, `debits - credits`; for credit-normal accounts, `credits - debits`

## Services
- `JournalService` — creates and posts journal entries, enforces balance invariant
- `TransferService` — inter-project fund movements, creates balanced entries with receivable/payable tracking
- `PayrollService` — generates payroll runs, computes payslips, posts salary entries
- All financial services wrap writes in `DB::transaction()`
